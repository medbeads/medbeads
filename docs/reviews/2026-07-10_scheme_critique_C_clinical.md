# スキーム批判レビュー 視点C: 臨床適合性(「人のメモに対抗できるか」)

2026-07-10 実施。4つの実診療場面のウォークスルーに基づく批判。

## 前段: 4場面ウォークスルー

- **場面1(外来再診の直前参照)**: 必要なのは「アクティブな問題・現行処方・前回からの変化・
  懸案」。retrieve は query/antigens 必須で「まず全体像」の入口がない。clinicalStatus は
  content に埋没しインデックス列がない。**状態(state)と変化(delta)が両方欠落**
- **場面2(退院サマリ)**: 実 ingest の親エッジは「Encounter→Patient / その他→自分の
  Encounter」の2規則のみで、DAG は**2階層の星形**。FHIR の reasonReference(因果)は
  親エッジ化されない。**「DAG が因果を運ぶ」は実データでは「同一受診グルーピング」に縮退**
- **場面3(当直申し送り)**: sibling_link は全て severity=warning・機械文で優先度の弁別力ゼロ。
  医師の warning(懸念)を入れる Bead 型が存在しない
- **場面4(インシデント振り返り)**: 判断 Bead(入力を parents に持つ)は未実装スコープ。
  記録時刻とイベント時刻が分離されず(bitemporality なし)「その時点で何が見えていたか」を
  再構成できない

## 批判(重要度順)

1. **医師の自由記述(narrative)が構造的に存在しない【致命的】** — Synthea の臨床ノート
   (DocumentReference)を ingest から除外し、自由テキスト用 Bead 型もない。104万 Bead に
   医師の文章が1文字も無い。「対抗どころか土俵に上がっていない」。
   改善: clinical_note 型(順序保存・非破壊)+ DocumentReference の取り込み
2. **アセスメント(A)と臨床推論の痕跡に居場所がない【致命的】** — SOAP の価値の核 = A/P
   (なぜそう判断したか、何を鑑別から消したか)を格納する型が無い。
   改善: assessment 型(parents = 根拠 Bead 群 — multi-parent DAG の本来の用途)
3. **「今の状態」(active problem list / 現行処方)が導出不能【致命的】** — 状態導出層が無く、
   エージェントは「今飲んでいる薬」を全走査と推測でしか答えられない。
   改善: 正本から再構築可能な導出ビュー(active_conditions / active_medications)
4. **看板ユースケース「eGFR低下↔腎排泄薬」が現行抽出では構造的に発生しない【重大】** —
   observation は loinc:/snomed: しか持てず organ:renal は薬剤側にしか付かないため、
   共有 antigen が生じない。改善: LOINC→organ/risk 辞書(数十行で書ける)
5. **トークン予算詰め込みが臨床的重要度・鮮度を反映しない【重大】** — tier 内 timestamp
   昇順のため、予算超過時に**最新の記録から切り捨てられる**。異常値・重症度・鮮度の概念が
   ない。改善: 新しい順 + 異常フラグ/重症度スコアリング
6. **L0/L1 レンダリングが臨床テキストを破壊する【重大】** — renderL0 は content 文字列を
   アルファベット順ソートで連結(文順粉砕)。要約はバイト位置切断で日本語を中途破壊。
   改善: type 別 FHIR-aware flattener、narrative は順序保存パススルー
7. **AI が「書く」側に回るループが存在しない【重大】** — AI 起草 → 医師承認(draft、
   承認 Bead、supersedes/amends)の設計が仕様にも実装にもない。
   改善: amends/retracts エッジ + 承認 Bead + retrieve の自動降格
8. **一律 severity=warning はアラート疲労とハルシネーションの供給源【重大】** — LLM は
   warning ラベルを相互作用・禁忌と読み替えて過剰生成しがち。測るはずのハルシネーションを
   自作リンクが押し上げるリスク。改善: 共起は info 固定、warning 以上は知識ベース裏付き限定
9. **時間軸が単線で bitemporality も期間もない【中】** — 記録時刻とイベント時刻の区別、
   入院期間、遅延入力の扱いが不能。改善: recorded_at(meta)+ as-of クエリ
10. **「まず患者の全体像」を返す入口ツールがない【中】** — 3分プレビジットが自作ループに
    なり人の SOAP メモ1枚に負ける。改善: brief(patient_id, token_budget) ツール
11. **clearance がエージェントの文脈を無音で欠落させ、仕様(ゴーストレコード方式)とも
    矛盾【中】** — 秘匿件数の信号すらなく、薬を隠された AI は相互作用チェックで「存在しない」
    と扱う。改善: withheld_count + 薬剤系秘匿時の警告
12. **L1 要約が retrieve 経路で常に死んでいる【軽微】** — Bundle が summary を運ばず常に
    フォールバック。改善: LoadBundle に summary 列を同乗

## 守る価値のある強み

1. 内容ハッシュ + parents による**判断根拠の暗号学的固定** — 人のメモには絶対に真似できない価値
2. トークン予算付き retrieve の「**切り捨て分を必ず列挙**」— エージェントが「知らないことを
   知っている」状態を保てる誠実な API 契約(RAG の無音欠落より本質的に優れる)
3. 決定論への徹底した規律(JCS、インジェスト LLM 禁止、決定論 timestamp)

## 総括

現状の MedBeads v3 は「構造化イベントの改ざん不能な倉庫 + 受診単位グルーピング検索」としては
堅牢だが、人のメモが運ぶ3つのもの — **状態(今どうか)、推論(なぜか)、優先度(何が重要か)** —
をいずれも持たない。勝負すべき土俵(narrative と assessment)を ingest 段階で自ら除外している
点が最大の自己矛盾。
